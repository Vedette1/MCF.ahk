# MCF (MCode Forge)

MCF — COFF-линковщик, реализованный на AutoHotkey v2, и частично C / C++.
Предназначен для сборки позиционно-независимого машинного кода (MCode) непосредственно в память.

![Screenshot](https://github.com/Vedette1/MCF.ahk/blob/main/screenshot1.png)

## О проекте

MCF — это линковщик объектных файлов формата COFF, заточенный под генерацию MCode (загрузчик машинного кода в память).
Он не зависит от конкретного компилятора: принимает готовые `.o` / `.obj` файлы, полученные из C, C++, Zig или любого другого языка, способного генерировать COFF.

Основная задача — превратить один или несколько объектных файлов в единый блок машинного кода с разрешёнными релокациями и картой символов, готовый к вызову через `DllCall`.

Имейте в виду, что MCF разрабатывается под GCC. Несмотря на то, что COFF-формат жестко регламентирован, у разных компиляторов есть свои особенности, из-за чего некоторый код невозможно собрать с помощью MSVC, например.

Также имейте в виду, что MCF не всесилен, и он очень далек от полноценных линковщиков вроде ld.exe. Но тем не менее MCF способен собирать 95% кода на C без изменений исходного кода, а также 10% кода на C++.

## Архитектура

Линковщик стремится повторять поведение обычных линкеров (ld, link.exe и т.д.), но вместо сборки PE/ELF формирует непрерывный буфер машинного кода.

Основные этапы:
- разбор COFF-заголовков, секций и таблицы символов;
- построение layout с учётом выравнивания;
- применение внутренних и внешних релокаций;
- формирование компактного IAT-хвоста для импортов;
- экспорт карты смещений символов и секций.

## Графический интерфейс

Проект включает GUI, который объединяет:
- настройку параметров линковщика;
- таблицы символов с деманглингом;
- информацию о COFF-файле;
- лог работы;
- обёртки компиляторов (компиляция → obj → MCode одной кнопкой);
- простой текстовый редактор с базовой подсветкой синтаксиса;
- инструменты для работы со статическими библиотеками (`.a` / `.lib`): извлечение объектных файлов и поиск символов.

GUI не является обязательным — линковщик может использоваться и программно.

## Пример

```ahk
/**
#include <windows.h>
int msgBox() {
	return MessageBox(0, "Hello Mcode", "Title", 0);
}
*/
; compiler : TDM-GCC 10.3.0
; flags    : -m64 -O2 -fPIC -fno-stack-protector -fno-plt -fno-asynchronous-unwind-tables

offset := Map()
offset["msgBox"] := 0x0 ; 2
offset[".text"] := 0x0 ; 4 [dispensable]
offset[".data"] := 0x20 ; 6 [dispensable]
offset[".bss"] := 0x20 ; 8 [dispensable]
offset[".rdata"] := 0x20 ; 10 [dispensable]

ptr := GetMcodePtr("4531c94c8d0516000000488d151500000031c9ff2500000000909090909090905469746c650048656c6c6f204d636f6465000000000000000000000000000000|User32:MessageBoxA:21:4") ; Copy the GetMcodePtr function from the GUI.
DllCall(ptr, "int")
```

## Текущие ограничения
- SEH (Structured Exception Handling) - `try / catch` не поддерживаются. Реализация потребует регистрации таблиц исключений `(.pdata / .xdata)` и в ближайшее время не планируется.
- Thread Local Storage (TLS) - Не поддерживается и, вероятнее всего, не будет реализован, ибо это супер сложно.
- COMDAT - Не реализованы стратегии `IMAGE_COMDAT_SELECT_LARGEST` и `IMAGE_COMDAT_SELECT_ASSOCIATIVE`.
- Global Constructors / Destructors - Секции вида `.CRT$XCU, .init_array, .ctors` и аналогичные не обрабатываются. Код, который должен выполняться до/после точки входа, не вызывается.
